## Sealed capture replays: 51

Session scripts read absolute paths stored in their inputs, read sibling session
folders and write outputs into siblings. So each run swaps a copy in at the
original path. The original root is renamed aside, copied back (ACD/BAK
excluded) with a marker, and only that run's own recorded outputs are removed
from the copy. The recorded command then runs unchanged, and the marked copy is
removed while the original is renamed back. Every phase is journaled, and
`recover_swaps_02.py` restores an interrupted swap. Pre-existing original files
were read-only during the runs: 13,191 in run 01, 24,797 in run 02 and 3,568 in
run 03. Fingerprints before and after are identical in every run, and every
swap was restored.

**Run 01 failed as apparatus and is kept.** It copied only each script's folder
elsewhere and reproduced 8 of 52. The cause was absolute paths inside inputs,
missing sibling folders and create-only outputs. Its `FileExistsError` cases
were scripts writing into original sibling folders. The read-only guard and
create-only opens refused them, and nothing original changed.

**Run 02 (swap-in-place):** 40 of 51 reproduce exactly as recorded. Of these, 36
have byte-equal canonical JSON outputs. The other four are three recorded
failures that fail again with identical final messages, plus a fixture
materializer whose Dart output is byte-identical to the sealed file. The other
11 are each explained by a recorded cause:

| Replays | Today | Recorded cause |
|---|---|---|
| 4 × S3k `replay_prior` | exit 0, `passed: true`, **every sealed row still present** | The replay globs the evidence tree, which gained captures later: sealed 1,431/1,385/1,385/1,385, now 1,523/1,516/1,516/1,516 |
| 5 × press/S3k Access/configuration pairs | Only `ConfigPage…/WriteRevision` differs | S5 write-revision correction (commit `8cd2060f1`): typed profiles publish the live owner revision instead of the build hash |
| S3j attempt | Only Unit `Diagnostic/IoAddress`/`IoTag` of one capture | S3j retry's recorded reference I/O-join correction; the corrected replay of all 41 captures (also re-run here) reproduces exactly |
| S3D first replay | Its script now writes `capture_replay_02` | Revised in-session; the accepted record cites `capture_replay_02`, which reproduces exactly |

**Run 03** tests the `WriteRevision` claim across every pair, not just the first.
In the swapped copy only, each of the five scripts' strict reference assertion
tolerates differences solely on paths ending `/WriteRevision` with equal types.
It records each such difference, restores the sealed value and continues. Any
other difference still fails. All five then reproduce their sealed outputs
exactly over **226 pairs**. The sealed values are the two former build hashes
(`5480224` press, `14896938` genealogy); today's are each capture's live owner
revision. Run 02's script is unchanged; run 03 loads it with anchored edits.
