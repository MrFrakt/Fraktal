# Nested Unit and manual routing bench

`make_fixture.py <new-package> <new-frames>` derives the existing Unit bench and
adds Satellite and Inner Unit types. The two roots contain 24 module instances
in 32 registry slots. Root modes include CHANGEOVER; nested Units omit it.
CM command catalogs and directional release reactions are generated from the
declaration. Root A explicitly owns the local carrier; peers remain independent.

Build the copied station with Generator/build.plan and the approved S12 runner's
--require-clean-compile gate. Download through the isolated virtual target guard.
Run probe_web.py through S12_TypeMap/with_secret.ps1 -Action script. Every mutation
and STOP/RUN act verifies the1516 TCPIP169.254.212.49 target and zero physical
mappings. The original pin and process-data-only web role are retained.

Catalog discovery now uses QUERY_CONFIG instead of reading private catalog symbols.
The native series covers catalog discovery, manual access/directional/common
release rollup, query purity, same normal command handshake and automatic Execute
drop, root/target scope, nested owning-mode/permit checks, trusted Start/Stop/reset
cascade, unsupported modes, general action gates, deferred/immediate exits and
STOP/RUN with fresh commands. Native child mailbox writes are refused. Test-only
local operations change a nested Unit and prove that independent calls still
check access. Read-only observations and private request storage keep that
stimulus separate from production generation.

JSON-lines and JUnit record each check and whether the probe completed. Failed
mutations are never replayed. Use a fresh guarded download before repeating the
series; its baseline depends on fixture initialization. This does not establish
GUI rendering, held manual commands, full alarm/audit/retention or press behavior.
